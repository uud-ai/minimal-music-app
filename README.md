# Minimal Music

Минималистичный музыкальный PWA-плеер: поиск треков через YouTube Data API, воспроизведение через скрытый YouTube IFrame Player, личная библиотека («Моя музыка») на Firebase (Firestore + анонимная авторизация).

Прод: **https://minimal-music-app.vercel.app**

## Стек

- Ванильный JS (ES-модули), без фреймворка
- [Vite](https://vitejs.dev/) — dev-сервер и сборка
- YouTube Data API v3 — поиск
- YouTube IFrame Player API — воспроизведение
- Firebase: Firestore (хранение лайкнутых треков) + Authentication (Anonymous)
- Service Worker — офлайн-кэш статики (PWA)
- Деплой: Vercel (автодеплой из `main`)

## Структура

```
index.html          разметка + панель плеера
main.js             вся логика: поиск, плеер, Firebase
styles.css          стили
public/
  manifest.json     PWA-манифест
  sw.js             service worker
  icon-*.png        иконки PWA
firestore.rules      правила доступа к Firestore (задеплоены)
firebase.json / .firebaserc   конфиг Firebase CLI
```

Всё, что лежит в `public/`, Vite копирует в сборку как есть — это важно, потому что `vite build` иначе подхватывает только файлы, на которые есть прямая ссылка в `index.html`, а `sw.js` и часть иконок ссылаются друг на друга через `manifest.json`/рантайм-строки, а не через теги в HTML.

## Разработка

```bash
npm install
npm run dev       # dev-сервер Vite
npm run build     # прод-сборка в dist/
npm run preview   # локальный просмотр сборки
```

## Настройка ключей

В `main.js` два места с конфигурацией, которые нужно заполнить своими значениями при разворачивании проекта с нуля:

1. **`YOUTUBE_API_KEY`** — ключ YouTube Data API v3 из [Google Cloud Console](https://console.cloud.google.com/apis/credentials). Обязательно ограничь его по HTTP referrer (домен деплоя), иначе квоту может исчерпать кто угодно, кто найдёт ключ в исходниках фронтенда.
2. **`firebaseConfig`** — конфиг веб-приложения из Firebase Console (Project settings → General → Your apps) или `firebase apps:sdkconfig WEB <appId>`. Сам `apiKey` в этом объекте не секрет — безопасность обеспечивают правила Firestore (`firestore.rules`), не сокрытие конфига.

## Firebase: база и правила

Проект: `minimal-music-app-e3bd3`.

- Firestore Database должен быть создан (Native mode).
- Authentication → Sign-in method → **Anonymous** должен быть включён — библиотека привязывает лайкнутые треки к анонимному `uid` устройства.
- Правила Firestore лежат в `firestore.rules` и ограничивают чтение/удаление документа только его владельцем (`request.auth.uid == resource.data.uid`). Задеплоить после изменений:

```bash
npx firebase-tools deploy --only firestore:rules --project minimal-music-app-e3bd3
```

## Треки канала

Имя канала под названием песни кликабельно: открываются остальные видео этого канала (YouTube `search` с `channelId`, популярные сверху, без фильтра по категории «Музыка» — каверы и нейросетевые песни авторы часто ставят в другие категории). «← К поиску …» возвращает прежние результаты без нового запроса. У лайкнутых треков `channelId` сохраняется в `liked_tracks`, поэтому автор кликабелен и в «Моей музыке» (у треков, лайкнутых до появления функции, — нет). Каждый такой переход тратит 100 единиц квоты, как обычный поиск.

## Мероприятия

Вкладка «Мероприятия» — сценарий вечера для организатора (корпоратив, детский праздник, официальный приём, свадьба). Мероприятие создаётся по шаблону блоков и хранится в Firestore, коллекция `events`, одним документом вместе с блоками.

- Блок — отрезок программы со своей музыкой: «фон по кругу» или «сигнал, один раз» (выход, награждение, гимн). Блок без треков — тишина.
- Треки в блок добавляются из «Поиска» и «Моей музыки» кнопкой ＋.
- «Режим ведущего» — полноэкранный пульт: видимый YouTube-плеер, текущий блок, «Следующий блок» с плавным затуханием, весь сценарий списком. Экран не гаснет (Screen Wake Lock).

## Игры и шаблоны

Игра — режим блока сценария («🎮 Игра» в блоке). Блок с игрой запускается на пульте ведущего (пульт открывается сам):

- **🧊 «Замри»** — музыка встаёт в случайный момент (8–25 с), на экране «ЗАМРИ!» и кнопка «▶ Музыка!»; есть «Замри сейчас».
- **❓ «Угадай мелодию»** — треки блока в случайном порядке по 15 с, видео и название скрыты до «👁 Ответ»; «▶ Дольше», «Следующий», табло команд (сохраняется на устройстве).
- **🎱 Музыкальное бинго** — песни по 30 с в случайном порядке, на пульте список сыгранных. Карточки: на телефоны гостей по QR (`/?bingo=<id>`, названия песен публикуются в `public_events/<id>.bingo`, карточка и отметки хранятся у гостя, линия — «🎉 БИНГО!») или печать («🖨 Карточки», 2 на страницу). Нужно от 9 разных песен: 9–15 → карточка 3×3, от 16 → 4×4.

Шаблоны: в корпоративе есть блоки бинго и «Угадай мелодию», в детском празднике — «Замри», отдельный шаблон «Квиз-вечеринка». «📋 Копия» дублирует мероприятие вместе с треками и играми.

## Заказы песен гостями по QR-коду

В мероприятии блок «📱 Заказы гостей»: переключатель приёма заказов, QR-код и ссылка `/?guest=<id мероприятия>`. Гость открывает её на телефоне без установки и регистрации (анонимный вход), ищет песню на YouTube или пишет название сам и видит статус своих заказов вживую.

- Организатор видит новые заказы вживую, одинаковые складываются («×3» — заодно голосование). «✓» добавляет песню в выбранный блок (если блок сейчас звучит — сразу в его очередь); заказ без поиска открывает поиск с этим названием. «✕» — отклонить.
- В режиме ведущего — счётчик новых заказов с панелью и «QR для гостей» на весь экран.
- Firestore: `public_events/<id>` — только название и `requestsOpen` (мероприятие гостям не видно), `requests` — заказы. Правила: гость создаёт заказ только при открытом приёме и видит лишь свои; организатор видит заказы своего мероприятия и меняет у них только статус. У гостя не больше 3 заказов в ожидании (проверка на клиенте).
- Удаление мероприятия удаляет его публичную карточку и заказы.

## Свои аудиофайлы

В «Моей музыке» можно загрузить свои MP3 (и другие аудиофайлы) — они играют через обычный `<audio>`, без YouTube: нет запретов на встраивание, работает перемотка и звук при заблокированном экране. Свои файлы добавляются в блоки мероприятий так же, как треки YouTube.

Файлы хранятся в **Cloudflare Workers KV** (бесплатный тариф без привязки карты — R2 требует карту) через воркер `worker/` → `https://minimal-music-files.uudnik.workers.dev`:

- `PUT /upload?name=…`, `GET /list`, `DELETE /files/<key>` — по Firebase ID-токену (тот же анонимный вход); ключ файла `<uid>/<uuid>/<имя>`, чужие файлы не видны и не удаляются.
- `GET /files/<key>` — открытая отдача с поддержкой `Range` (без неё Safari не играет аудио).
- Лимиты KV Free: до 25 МБ на файл, 1 ГБ всего, 1000 загрузок в сутки. Список обновляется с задержкой до минуты — фронтенд сам помнит только что загруженные/удалённые файлы.

Деплой воркера:

```bash
cd worker && npx wrangler deploy
```

## Аккаунт (необязательно)

Без входа всё работает на анонимном `uid` устройства. Кнопка в шапке открывает вход **через Google** или **по почте с паролем** (со ссылкой «Забыли пароль?» — Firebase присылает письмо для сброса). С аккаунтом мероприятия, «Моя музыка» и свои файлы доступны на всех устройствах.

- Первый вход на устройстве превращает анонимную сессию в аккаунт (`linkWithPopup` / `linkWithCredential`) — `uid` и данные остаются прежними.
- Вход в уже существующий аккаунт на другом устройстве переносит в него данные этого устройства: лайки (без дублей) и мероприятия копируются в Firestore, свои файлы перекладывает воркер (`POST /migrate`), скачанные для офлайна копии переезжают вместе с ними.
- В Firebase Auth включены провайдеры Anonymous, Google и Email/Password; `minimal-music-app.vercel.app` добавлен в Authorized domains.

Проверка входа по почте локально, без настоящих аккаунтов — эмулятор Firebase Auth:

```bash
npx firebase-tools emulators:start --only auth   # порт 9099, см. firebase.json
# в консоли браузера на localhost:5173: localStorage.authEmulator = '1', затем перезагрузить
```

## Известные ограничения

- Без входа в аккаунт библиотека и мероприятия привязаны к браузеру/устройству: очистка данных сайта или другое устройство — новый `uid`, старые данные не видны.
- Официальные треки лейблов часто нельзя встраивать (ошибка плеера 150) — такие треки помечаются зачёркнутыми и пропускаются.
- YouTube API квота ограничена (10 000 unit/день по умолчанию), у поиска высокая цена запроса — при активном использовании квота может закончиться раньше полуночи по Тихоокеанскому времени.
